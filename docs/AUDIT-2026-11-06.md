# Auditoría conservadora v52

Revisión del proyecto local el 6 de noviembre de 2026. Se partió de v51 y del
repositorio Git limpio, sin descartar cambios ni borrar archivos ajenos.
La auditoría anterior de v49 se conserva como documento histórico.

## Conservación y alcance

- Copia previa recuperable: `.backups/v51-before-audit-2026-11-06-001709.zip`.
  Se conservan también las copias v33 y v48.
- CSV, marca, fuentes, bibliotecas e iconos: 19 archivos comparados byte a byte
  con la copia previa, todos idénticos. Se mantienen 27 registros, 17 elementos
  físicos y 7 isótopos, incluidos el registro sin fecha y sus limitaciones.
- Se conserva el esquema 2, sus claves y las migraciones existentes. No se
  cambia ninguna semivida, fórmula, tolerancia ni dato metrológico.
- Se revisaron los módulos propios, coordinación, HTML, CSS, manifiesto,
  worker, generador de publicaciones, servidores y batería de pruebas. Se
  mantuvo la arquitectura modular previa, evitando una reescritura innecesaria.
- Las pruebas utilizan perfiles temporales. No se accedió al almacenamiento
  del navegador habitual del usuario ni se migraron sus datos reales.

## Cambios comprobables

1. **Almacenamiento:** una lectura que lanza una excepción ya no equivale a una
   clave vacía. Desde ese fallo se bloquean las escrituras hasta recargar. La
   exportación sigue conservando el modelo visible y advierte si faltan claves
   que no pudieron leerse. No se sobrescribe el principal ni las copias.
2. **Recuperación:** se comprueba la estructura de cada entrada de la historia,
   evitando una excepción con valores como `[null]`. Se conserva el original
   y se ofrece exportar. Se impide que el contador de revisiones desborde.
3. **Coordinación:** los fallos síncronos al abrir IndexedDB o su transacción
   se convierten en mensajes accionables, conservando Web Locks y la alternativa
   IndexedDB para las escrituras entre pestañas.
4. **Offline:** descargas verificadas con cancelación a los 15 segundos. Reparar
   una caché ya íntegra offline confirma su disponibilidad; el fallo de la
   consulta de actualizaciones no anuncia falsamente que faltan recursos.
5. **Etiquetas:** la documentación las anunciaba, pero v51 no ofrecía controles
   ni generador. Se añade un módulo pequeño que reutiliza las tarjetas y la
   paginación corporativas: 1–100 copias por elemento, máximo 1000 por archivo,
   selección filtrada, Bq, Bq/g, masa, límites y descriptores. No duplica datos
   persistidos ni presupone una plantilla comercial de papel adhesivo.
6. **PDF coherente:** selección, fecha e isótopos se capturan antes de las esperas.
   El PDF y el texto compartido permanecen en el mismo modelo si otra pestaña
   modifica el inventario durante la captura.
7. **Rango numérico:** se rechaza al leer una conversión Bq/g × masa positiva
   que subdesborda a cero. El formato visual usa notación científica para
   cantidades pequeñas que de otro modo se mostrarían como cero.
8. **Mantenimiento:** pruebas de publicación y actualización toman las versiones
   del paquete/manifiesto, evitando volver a fijarlas manualmente en cada
   publicación. Las esperas de control del worker tienen límite en las pruebas.
   Se corrige la referencia errónea a A4 vertical en el README.

## Verificación reproducible

`npm test` comprueba sintaxis de 26 archivos JavaScript, huellas de los 31
recursos de v52, 49 pruebas unitarias/repositorio/worker y 10 pruebas de datos,
además de la matriz de navegador. La sintaxis Python se verifica con `ast.parse`
y la de PowerShell con su analizador nativo.

La matriz cubre Chromium, Chrome y Edge instalados, WebKit, Android, iPhone e
iPad emulados; CRUD, incertidumbres y tolerancias, Bq y Bq/g, búsqueda, filtros,
agrupación, impresión horizontal, PDF y etiquetas, anchos 320/390/768/1440,
almacenamiento bloqueado o lleno, lecturas revocadas, concurrencia real, APIs
opcionales ausentes, caché incompleta, reparación y actualización real entre
dos publicaciones. Una prueba pausa la captura PDF y escribe desde otra
pestaña para comprobar la consistencia del documento y del texto compartido.

Los resultados finales se guardan en `tests/output/audit-results.json`. Las
muestras PDF y capturas v52 quedan en ese directorio, que el servidor no publica.
Se renderizan con Poppler para revisar visualmente las páginas completas del
informe, etiquetas offline, agrupación extensa e impresión. Se comprueban
logotipo, fuentes, tres columnas, continuidad de registros, márgenes y pies.

Ejecución final de `npm test`: código de salida 0; 59 pruebas unitarias y de
datos aprobadas, 36 comprobaciones de navegador aprobadas, cero fallos y una
no disponible (Firefox). Resultado generado el 06/11/2026 a las 00:29:20 de
Madrid (05/11/2026 23:29:20 UTC).

La revisión visual cubrió el informe normal y offline de tres páginas, las
etiquetas offline filtradas, las etiquetas completas de iPad de tres páginas,
la agrupación extensa de dos páginas y las cinco páginas de impresión ampliada.
No se observaron recortes, solapamientos, pérdida de logotipo o registros.
Se conservan la composición y el tamaño de letra acordados. La aplicación
queda servida localmente en `http://127.0.0.1:8080/` durante esta sesión.

## Límites de la verificación

- Firefox de Playwright sigue sin completar su arranque en este Windows. Se
  registra como no disponible, nunca como prueba aprobada.
- Los perfiles emulados no sustituyen dispositivos físicos. Quedan pendientes
  instalación y diálogos nativos de compartir/impresión en los dispositivos
  reales y una instalación funcional de Firefox.
- El PDF conserva la composición rasterizada existente: no contiene texto
  seleccionable ni estructura accesible. El inventario HTML ofrece el contenido
  textual accesible. No se añadió un importador automático de copias JSON.
- El límite de 1000 etiquetas evita una selección sin cota; no certifica que
  todo dispositivo físico disponga de memoria suficiente para ese máximo.

No se limpiaron datos operativos ni archivos ajenos. Solo se retiran las imágenes
intermedias de renderizado creadas durante esta ejecución. Para arrancar se
conserva `server.ps1`; para otra publicación, usar un número mayor que 52 con
`scripts/release.mjs` y volver a ejecutar `npm test`.
